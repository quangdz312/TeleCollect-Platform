## 1. Hiện trạng codebase

**Kết luận: Backend gần như là bộ khung rỗng (skeleton), chưa có logic/API thật nào chạy được. Toàn bộ UI hiện tại chạy 100% bằng dữ liệu giả trong Frontend.**

### 1.1 Backend (`src/`)

- Có đủ cấu trúc thư mục theo kiến trúc dự kiến: `api/`, `core/`, `models/`, `services/`, `sim/`, `training/`, `export/`.
- `src/main.py`: app FastAPI đã khởi tạo được (CORS, lifespan, `/health`), **include router nhưng router không có endpoint nào**.
- 6 router trong `src/api/` (`auth.py`, `tasks.py`, `teleop.py`, `demos.py`, `datasets.py`, `training.py`): **mỗi file chỉ có docstring mô tả "Endpoint dự kiến" + khai báo `APIRouter(prefix=...)` rỗng, không có route (`@router.get/post/...`) nào cả.**
- `src/models/db.py`: chỉ có docstring mô tả bảng dự kiến (`users`, `episodes`, `datasets`, `dataset_episodes`, `training_jobs`) — **chưa có class SQLAlchemy nào**, chưa có `get_engine()`/`get_session()`/`init_db()`.
- `src/models/schemas.py`: **đã có đầy đủ Pydantic response/request models** (UserResponse, TokenResponse, TaskResponse, SessionResponse, DemoResponse, TrimRequest, ReviewRequest, DatasetResponse, TrainingJobResponse, EvalResultResponse...) — đây là hợp đồng API rất hữu ích, dùng lại được ngay.
- `src/models/enums.py`: **đã hoàn chỉnh** — `UserRole` (operator/reviewer), `DemoStatus` (recording→recorded→labeled→approved/rejected), `DemoOutcome`, `DatasetFormat`, `JobStatus`.
- `src/config.py`: **đã hoàn chỉnh và dùng được ngay** — `Settings` (Pydantic Settings) đọc `.env`, có `database_url` (SQLite+aiosqlite mặc định), `storage_dir`, `control_hz`, `jwt_secret`, `enable_face_anonymization`, tự tạo thư mục data lúc khởi động.
- `src/core/`, `src/services/`, `src/sim/`, `src/training/`, `src/export/`: chưa kiểm tra chi tiết logic bên trong, nhưng theo cấu trúc là nơi chứa control loop, recorder, anonymize, sim MuJoCo, training PyTorch, export LeRobot/RLDS — cần rà thêm khi vào từng module tương ứng.
- `ARCHITECTURE.md`: vẫn là **template mẫu chưa điền** (các mục `[mô tả]`, `[danh sách]`... còn nguyên placeholder, sơ đồ nhắc tới LangGraph/Vector Store không khớp với mô tả hệ thống thật ở đầu file) — không nên coi là tài liệu kiến trúc chính thức, hiện `docstring` trong từng file router lại là nguồn thông tin đáng tin hơn.

**Chốt lại: Backend = xương (schema, enums, config đã sẵn) nhưng chưa có thịt (route logic, DB models, service logic thật). Có thể coi mọi endpoint là "cần code từ đầu", chỉ khác là đã có sẵn *hợp đồng dữ liệu* để bám theo.**

### 1.2 Frontend (`frontend/`)

- Là bản **demo độc lập**, tự nhận trong comment: *"nothing here touches the network"*.
- `lib/api.ts`: client giả lập toàn bộ API thật (cùng tên hàm, cùng shape dữ liệu) nhưng đọc/ghi vào in-memory store (`lib/demo-data.ts`), lưu lại qua `localStorage`.
- `lib/demo-data.ts`: seed data xác định (deterministic RNG), tự sinh 46 demo mẫu, 3 export mẫu, 3 training run mẫu, 3 eval run mẫu.
- `lib/teleop.ts`: thay vì WebSocket tới simulator MuJoCo thật, chạy một **simulator vật lý đồ chơi ngay trong trình duyệt** (canvas 2D, pinhole camera giả, vật lý cube/gripper đơn giản) ở 30Hz.
- Đăng nhập giả: bất kỳ username/password nào cũng vào được, role suy từ tên đăng nhập.

## 3. Đối chiếu nhanh: gap giữa Pydantic schema hiện có và dữ liệu Frontend cần

- Enum `UserRole` thiếu `ADMIN` (frontend có 3 role: operator/reviewer/admin).
- `TaskResponse` (backend: name/description/action_dim/max_steps) lệch field với `Task` (frontend: id/title/instruction/max_steps/hints) — cần họp thống nhất 1 contract, khuyến nghị **backend giữ nguyên, frontend thật sẽ map lại** (đây là việc của người phụ trách frontend, không phải việc của bạn — chỉ cần bạn công bố schema chuẩn).
- `DemoResponse`/`DemoDetailResponse` backend thiếu nhiều field frontend demo dùng: `seed, fps, num_frames, duration_s, size_bytes, auto_success, auto_success_frame, latency_p50/p95_ms, control_jitter_ms, dropped_frames`.
- Chưa có endpoint `summary`, `trajectory`, `reopen` demo, `dvc status`, `training log/history` — cần bổ sung vào thiết kế trước khi code.
- `EvalResultResponse` thiếu `mean_episode_length`, `details`, CI.

*(Đây là điểm cần bạn quyết định: giữ đúng theo `ARCHITECTURE.md`/docstring hiện có làm chuẩn, rồi yêu cầu frontend thật điều chỉnh; hay mở rộng schema cho khớp UI demo. Khuyến nghị: bám theo nhu cầu UI thật vì đó là specs đến từ người dùng cuối.)*

## 4. Lộ trình phát triển Backend (theo module, làm xong — test kỹ — mới sang module tiếp)

Nguyên tắc làm việc đã thống nhất: **code xong 1 module → viết test → chạy pass → mới chuyển module kế tiếp.**

| 0      | **Nền tảng dữ liệu**                                                                                                            | `src/models/db.py`: định nghĩa SQLAlchemy models (`users`, `episodes`, `datasets`, `dataset_episodes`, `training_jobs`), `get_engine/get_session/init_db`, cấu hình Alembic (nếu dùng migration).                     | Mọi module sau đều cần DB layer chạy được trước.                                                                                                                                                 |
| 1      | **Auth** (`src/api/auth.py` + `src/services/security.py`)                                                                       | Hash password,`POST /auth/login`, `POST /auth/refresh`, `GET /auth/me`, dependency `current_user`/`require_role`. Bổ sung `UserRole.ADMIN`. Quản lý user (CRUD) cho admin.                                                  | Mọi API khác đều cần xác thực/phân quyền — làm trước để mock được các module sau bằng user thật.                                                                                      |
| 2      | **Tasks** (`src/api/tasks.py` + `src/sim/tasks.py`)                                                                             | `GET /tasks`, `GET /tasks/{name}`, `GET /tasks/{name}/stats`.                                                                                                                                                                        | Danh mục task là input cho cả Teleop lẫn Demos — cần có sớm, độ phức tạp thấp, dễ test.                                                                                                      |

## 5. Ghi chú quan trọng khác

- Theo `CLAUDE.md` của dự án: bạn chỉ phụ trách Backend, **không sửa code Frontend**. Bản `frontend/` hiện là **demo tách biệt hoàn toàn** — không có API call thật nào để nối dây; việc nối frontend thật với backend là việc của người phụ trách frontend, dựa trên các API bạn công bố.
- `ARCHITECTURE.md` hiện là file mẫu (template) chưa điền — nên coi các phần "Agent/LangGraph/Vector Store" trong đó là rác thừa từ template, không áp dụng cho dự án này (dự án không có AI Agent/LLM), cần trao đổi để dọn lại tài liệu này, không tự ý sửa.
